## Costo computacional (n ejemplos, d features)

| Modelo | Entrenar | Predecir | Escala a millones |
| --- | --- | --- | --- |
| OLS / ridge (forma cerrada) | $O(nd^2 + d^3)$ | $O(d)$ | sí con SGD |
| Logística | iterativo, $O(nd)$ por época | $O(d)$ | sí (SGD) |
| Naive Bayes | una pasada de conteos, $O(nd)$ | $O(d)$ | **sí, el más rápido** |
| LDA / QDA | $O(nd^2 + d^3)$ | $O(d^2)$ | sí si d es moderado |
| SVM con kernel | $\sim O(n^2)$–$O(n^3)$, Gram $n\times n$ | $O(\#\text{SV}\cdot d)$ | no (usar SVM lineal) |
| Kernel ridge | $O(n^3)$, memoria $O(n^2)$ | $O(nd)$ | no |
| Árbol | $\approx O(pn\log n)$ | $O(\text{profundidad})$ | sí |

## Reglas que se repiten en el examen

1. **Pocos datos o necesitas la densidad** ⇒ generativo (NB, LDA). **Muchos datos y solo la etiqueta** ⇒ discriminativo (logística, SVM).
2. **Frontera lineal suficiente** ⇒ empieza lineal: es más rápido, interpretable y es tu *baseline*.
3. **Necesitas explicar** ⇒ logística (odds ratios), lasso (pocas features) o un árbol podado.
4. **Clases desbalanceadas** ⇒ no reportes accuracy: precision, recall, F1, ROC/PR; mueve el umbral.
5. **Muchas más features que ejemplos** ⇒ ridge/lasso, logística L2, SVM lineal o NB. Evita OLS y QDA.
6. **Todo hiperparámetro** (λ, C, γ, α de poda, profundidad) se elige con **validación cruzada**, nunca con el test.
7. **Estandariza** antes de cualquier método con distancias, normas o gradientes; los árboles no lo necesitan.
