## Todavía hay que elegir λ (o el grado)

Todo modelo tiene **hiperparámetros**: settings que eliges, no que se aprenden (λ de ridge/lasso, el grado, C y γ del SVM, el α de poda). Una sola partición train/validación es **ruidosa**: el «mejor λ» depende de qué puntos cayeron en validación, y con pocos datos cada punto separado es precioso.

## K-fold, paso a paso

1. Parte los datos (de entrenamiento) en $K$ bloques iguales (típico $K=5$ o $10$).
2. Para cada $k$: entrena con los $K-1$ bloques restantes y **valida** en el bloque $k$.
3. Promedia los $K$ errores ⇒ un score para ese valor del hiperparámetro.
4. Repite sobre una grilla de valores (λ en escala log) y quédate con el mínimo.
5. **Re-entrena** con todos los datos de entrenamiento usando el valor elegido y evalúa **una vez** en el test.

$$
\text{CV}(\lambda) = \frac1K\sum_{k=1}^K \text{Error}_k(\lambda),\qquad \lambda^\star = \arg\min_\lambda \text{CV}(\lambda)
$$

Cada punto se usa para validar **exactamente una vez**: una estimación más honesta y de menor varianza del error de generalización.

:::caution[Pregunta del banco]
«En K-fold, cada uno de los K bloques que se dejan fuera es un **test set** sobre el que se reporta el resultado final» → **Falso**. Son folds de **validación**: se usan para *elegir* el modelo. El test set queda fuera de toda la selección y se usa una sola vez al final.
:::

## La curva de CV y la regla de 1 SE

La curva CV vs λ tiene otra vez forma de **U**: poca penalización sobreajusta (izquierda), demasiada subajusta (derecha). Se grafica con ±1 **error estándar** entre folds.

**Regla de 1 SE:** entre todos los λ cuyo error CV está a menos de un SE del mínimo, elige el **más fuerte** (el modelo más simple). Las diferencias menores a un SE son ruido: obtienes un modelo más simple, estable e interpretable **gratis**. La misma regla se usa para podar árboles.

## Data leakage: el pecado capital

Hay fuga cuando información de evaluación influye en el entrenamiento, y los scores salen optimistas. Formas típicas:

- Elegir hiperparámetros mirando el **test**.
- **Estandarizar** (o imputar, o seleccionar features) usando *todo* el dataset antes de partir. El escalador se ajusta **solo con los folds de entrenamiento** y luego se aplica a validación/test (en scikit-learn: `Pipeline` + `GridSearchCV`).
- Series de tiempo partidas al azar (hay que respetar el orden temporal).

:::note[Maldición del ganador]
Si comparas muchos modelos en el mismo conjunto de validación, el ganador parece mejor de lo que es (incluso con datos de puro ruido). Por eso el test, visto una sola vez, da la nota honesta. Para evaluar el propio procedimiento de selección existe la **CV anidada**.
:::

En competencias tipo Kaggle hay un *leaderboard público* (una parte del test) y uno *privado* (el resto, revelado al final). Equipos que envían cientos de variantes y se quedan con la que mejor puntúa en el público suelen **caer muchos puestos** en el privado: hicieron selección de modelos sobre el test público, exactamente la maldición del ganador del simulador de arriba. Los que eligen con una **validación cruzada local** sólida y miran poco el leaderboard suelen subir.

Otra fuga clásica: **series de tiempo** partidas al azar. Si el modelo de demanda entrena con datos de marzo y valida con febrero, «ve el futuro». Se usa una partición temporal (`TimeSeriesSplit`): siempre entrenar con el pasado y validar con lo que viene después.

## Ejercicio

Tienes 1000 ejemplos. Reservas 200 para test. Con los 800 restantes haces 5-fold CV para 10 valores de λ. ¿Cuántos modelos entrenas en total y con cuántos puntos cada uno?

<Solucion>

- CV: $5 \text{ folds} \times 10 \text{ valores} = 50$ modelos, cada uno con $800\cdot\tfrac45 = 640$ puntos (validando en 160).
- Luego **1** modelo final con los 800 puntos y el λ elegido, evaluado una vez en los 200 de test.
- Total: **51** entrenamientos.

</Solucion>

## En código: CV sin fugas

```python
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler, PolynomialFeatures
from sklearn.linear_model import Ridge
from sklearn.model_selection import GridSearchCV, KFold, cross_val_score
import numpy as np

# el escalador vive DENTRO del pipeline: en cada fold se ajusta solo con train
pipe = make_pipeline(PolynomialFeatures(9), StandardScaler(), Ridge())
grid = GridSearchCV(pipe, {'ridge__alpha': np.logspace(-6, 2, 30)},
                    cv=KFold(5, shuffle=True, random_state=0),
                    scoring='neg_root_mean_squared_error')
grid.fit(X_tr, y_tr)                         # el test no aparece aquí
print(grid.best_params_, -grid.best_score_)
print('test:', -grid.score(X_test, y_test))  # una sola vez, al final

# CV anidada: estima qué tan bueno es TODO el procedimiento de selección
outer = cross_val_score(grid, X_tr, y_tr, cv=5)
```
