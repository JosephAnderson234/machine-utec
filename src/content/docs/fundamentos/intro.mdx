## El problema de escribir reglas

Tarea: *¿esta foto contiene un gato?* Intenta escribir reglas: «tiene orejas puntiagudas» (pero a veces están dobladas u ocultas), «tiene pelo» (los perros y las alfombras también)… cien reglas después, el programa falla con la siguiente foto.

**No sabemos enunciar las reglas, pero sí podemos dar ejemplos.** Machine learning convierte ejemplos en un programa que funciona.

## Dos definiciones

- **Samuel (1959), informal:** el campo que da a las computadoras la capacidad de aprender *sin ser programadas explícitamente*.
- **Mitchell (1997), operacional:** un programa **aprende** de la experiencia $E$ respecto a una tarea $T$ y una medida de desempeño $P$ si su desempeño en $T$, medido por $P$, **mejora con** $E$.

Para cualquier proyecto de ML, fija siempre las tres piezas. Ejemplo del filtro de spam:

| Pieza | Qué es | Spam |
| --- | --- | --- |
| **T** (tarea) | lo que el sistema debe hacer | etiquetar cada correo como spam o ham |
| **P** (desempeño) | cómo medimos el éxito | % de correos bien clasificados |
| **E** (experiencia) | de qué datos aprende | correos etiquetados por los usuarios |

:::caution[Trampa del banco de preguntas]
$E$ **no** es el algoritmo de entrenamiento y $P$ **no** es el número de parámetros. $E$ son los datos; $P$ es una medida de qué tan bien se hace $T$.
:::

### La versión formal (opcional): minimizar el riesgo

Queremos una función $h$ con bajo **riesgo esperado** $R(h) = \mathbb{E}_{(\mathbf{x},y)\sim P}[\ell(h(\mathbf{x}), y)]$, el error promedio sobre *todos* los datos posibles. No conocemos $P$, así que minimizamos el **riesgo empírico** sobre los datos que sí tenemos:

$$
\hat R(h) = \frac{1}{n}\sum_{i=1}^{n}\ell\big(h(\mathbf{x}_i), y_i\big)\qquad\text{(ERM: empirical risk minimization)}
$$

Toda la tensión del curso está aquí: minimizamos $\hat R$ (lo que vemos) pero nos importa $R$ (lo que no vemos). La diferencia es la **generalización**.

<CasoUso titulo="Del problema de negocio al problema de ML: alquileres en Lima" sector="inmobiliario" icono="🏢">

Una inmobiliaria quiere sugerir el precio de alquiler de cada departamento nuevo. Antes de elegir un algoritmo, se **traduce** el problema:

| Pregunta | Respuesta |
| --- | --- |
| **T** (tarea) | predecir el alquiler mensual (S/) de un departamento |
| **P** (medida) | error típico en soles en departamentos *nuevos*: RMSE o MAE sobre un test set |
| **E** (experiencia) | 5 000 anuncios pasados con área, cuartos, distrito, antigüedad y su alquiler real |
| Tipo | supervisado, **regresión** (el target es un número) |
| Riesgo principal | que el modelo memorice anuncios repetidos o que un distrito «se filtre» entre train y test |

Cada fila del CSV es un ejemplo $(\mathbf{x}_i, y_i)$; las columnas área, cuartos… son las features $\mathbf{x}$; el alquiler es $y$. Es exactamente el dataset sintético `make_apartments` que usan los notebooks 01a–01e.

## Anatomía de un problema de aprendizaje

| Término | Símbolo | Ejemplo (dígitos 8×8) |
| --- | --- | --- |
| Features / entrada | $\mathbf{x}\in\mathcal X$ | los 64 píxeles |
| Target / etiqueta | $y$ | el dígito 0–9 |
| Dataset | $\mathcal D=\{(\mathbf{x}_i,y_i)\}_{i=1}^n$ | 1797 imágenes etiquetadas |
| Modelo | $\hat y = h_\theta(\mathbf{x})$ | una función con perillas $\theta$ |
| Pérdida | $\ell(\hat y, y)$ | costo de un error |
| Entrenar vs inferir | ajustar $\theta$ vs predecir | girar perillas vs leer la respuesta |

Los datos pueden ser **estructurados** (una tabla: cada fila un ejemplo, cada columna una feature, el orden de filas no importa) o **no estructurados** (una imagen es un tensor $\mathbb{R}^{H\times W\times 3}$ donde la disposición espacial sí importa). La lógica train/val/test es idéntica en ambos casos.

## Generalizar es todo el punto

Memorizar las respuestas de entrenamiento **no** es aprender. Por eso:

1. Se juzga a los modelos con datos **no vistos**, nunca con los de entrenamiento.
2. Se parte: **train** (ajustar) / **validación** (elegir y afinar) / **test** (nota final, una sola vez).

<Splits />

- **Underfitting:** el estudiante que solo aprendió «siempre responde C».
- **Overfitting:** el que memorizó las respuestas exactas del examen del año pasado.
- **Lo que queremos:** el que aprendió los conceptos.

Juega con el grado del polinomio: el error de entrenamiento siempre baja, pero el de validación hace una **U**.

## Cómo aprenden los modelos

Entrenar = **rodar cuesta abajo en la pérdida**. El descenso de gradiente mide la pendiente local y da un paso pequeño en la dirección opuesta; el tamaño del paso es la **tasa de aprendizaje** (ver [matemáticas](/fundamentos/matematicas/) y [descenso de gradiente](/regresion/gradiente/)).

### Por qué separar train, validación y test: un ejemplo con números

<Pasos titulo="Un ciclo de modelado honesto, paso a paso">

1. **Barajar y partir una sola vez.** 5 000 anuncios → 3 500 train (70%), 750 validación (15%), 750 test (15%). La partición se congela.
2. **Ajustar en train.** Se entrenan una regresión lineal y un árbol: RMSE de train = S/ 210 y S/ 15. El árbol parece genial…
3. **Comparar en validación.** RMSE de validación = S/ 230 (lineal) y S/ 410 (árbol). El árbol **memorizó**: la brecha 15 → 410 es overfitting. Se elige el lineal (o se poda el árbol).
4. **Afinar en validación**, nunca en test: por ejemplo, el λ de ridge. Cada decisión «mira» la validación, así que su score se vuelve un poco optimista.
5. **Medir una sola vez en test.** RMSE de test = S/ 236: esa es la cifra que se reporta, porque el test no influyó en ninguna decisión.
6. **Si después «arreglas algo» mirando el test**, el test se contamina (data leakage) y ya no tienes una estimación honesta.

</Pasos>

## Ética y ML responsable

- **Sesgo y equidad:** los modelos amplifican los sesgos de los datos → mide por grupos.
- **Privacidad:** los datos pueden memorizarse y filtrarse → recolecta lo mínimo.
- **Transparencia:** las personas merecen saber *por qué* y poder impugnarlo.
- **Responsabilidad:** humano en el circuito para decisiones de alto impacto.
- **Robustez y costo:** fallas, entradas adversarias, energía, mal uso.

## En código (scikit-learn)

```python
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_squared_error

# 70 / 15 / 15: primero se separa el test y no se vuelve a tocar
X_tmp, X_test, y_tmp, y_test = train_test_split(X, y, test_size=0.15, random_state=0)
X_tr, X_val, y_tr, y_val = train_test_split(X_tmp, y_tmp, test_size=0.15 / 0.85, random_state=0)

model = LinearRegression().fit(X_tr, y_tr)                  # E: aprender de train
rmse_val = mean_squared_error(y_val, model.predict(X_val)) ** 0.5   # elegir / afinar
# ... comparar modelos con rmse_val ...
rmse_test = mean_squared_error(y_test, model.predict(X_test)) ** 0.5  # UNA vez, al final
```
